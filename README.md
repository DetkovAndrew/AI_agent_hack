# Стратег Фабрики продуктов

ИИ-агент для руководителя цифрового продукта: от размытого запроса — к проверяемой картине
ситуации, нескольким разным вариантам и согласованным продуктовой и коммуникационной
стратегиям с планом проверки; после решения — сопровождение и пересмотр при новых данных.

Агент — это папка: инструкции (`AGENTS.md`), процедуры (`.claude/skills`), помощники
(`.claude/agents`), методики (`knowledge/`), инструмент учёта доказательств (`tools/pf.py`)
и проекты (`projects/`). Открывается в Claude Code (основная среда), Cursor или Codex.

## Быстрый старт

Требования: Python 3.10+, Claude Code (подписка Claude Pro/Max или ключ API Anthropic).
Других платных сервисов не требуется. Секреты в репозитории не хранятся.

```bash
git clone <repo> && cd <repo>
pip install -r requirements.txt      # опционально: PDF и XLSX
mkdir -p .claude && cp docs/claude-settings.proposed.json .claude/settings.json   # хуки и разрешения
claude                               # запустить Claude Code в корне репозитория
```
В чате: `/pf-start` и опишите задачу своими словами, например:
«Удержание в нашем приложении упало за полгода, надо понять, что делать. Вот выгрузка» —
и приложите файлы. Агент сам задаст нужные вопросы и поведёт работу по этапам.

Продолжить после перерыва (в том числе в новом чате): просто откройте `claude` — хук
покажет статус и следующее действие; или `/pf-start` → «продолжим».

**Cursor / Codex:** откройте папку; правила подхватываются из `AGENTS.md` / `.cursor/rules`.
Попросите агента «начни новый проект» или «продолжи».

**MCP** (`tools/mcp_server.py`, только стандартная библиотека). 19 инструментов поверх `pf.py`:
`pf_status`, `pf_fetch`, `pf_ingest`, `pf_claim_add`, `pf_check`, `pf_impact`, `pf_kb_search`… и `pf`
для любой другой команды. Каждый вызов запускает `pf.py`, поэтому проверки, блокировка и журнал
те же. Cursor подключает сервер из `.cursor/mcp.json` (Settings → MCP → включить `pf-strategist`).
Codex — в `~/.codex/config.toml`:
```toml
[mcp_servers.pf-strategist]
command = "python3"
args = ["/полный/путь/к/репозиторию/tools/mcp_server.py"]
```
В Claude Code сервер не подключён намеренно: там те же действия делают skills и `pf.py` через Bash,
а второй набор инструментов только путал бы модель.

## Как это устроено

```
Запрос PM ─► intake ─► collect ─► research ─► options ─► [PM выбирает] ─► strategy ─► validation ─► decision ─► tracking
                │          │          │           │                          │            │             │           │
           ключевые    реестр S   реестр C/G   варианты +              продукт +     план проверки   решения D   pf.py review /
           вопросы Q   (снимки,   situation.md red-team               коммуникации                   + отчёт     impact / revise
                       sha256)                                        + сверка judge
```

| Слой | Где | Что |
|---|---|---|
| Постоянные правила | `AGENTS.md`, `CLAUDE.md` | принципы, процесс, маршрутизация, безопасность |
| Процедуры этапов | `.claude/skills/pf-*` | пошаговые инструкции, вызываются как `/pf-...` |
| Помощники | `.claude/agents/*` | researcher (Sonnet), source-extractor (Haiku), data-analyst (Sonnet), red-team (Opus), synthetic-respondent (Haiku), judge (Haiku) |
| Методики | `knowledge/methods/` | стандарты доказательности, стратегии, интервью, данные, UX |
| Шаблоны результатов | `knowledge/templates/` | situation, options, стратегии, план проверки, summary |
| Материалы и состояние задачи | `projects/<slug>/` | state.json, STATUS.md, journal.md, sources/, evidence/, decisions/, deliverables/ |
| Инструмент | `tools/pf.py` | реестры, проверки, влияние изменений, стоимость, отчёт |

### Реестр доказательств
- **Источники `S…`** — веб-страницы, файлы PM, интервью, расчёты; снимок + извлечённый текст +
  sha256 + дата получения; проверка на попытки prompt-injection.
- **Утверждения `C…`** — тип (`fact` / `hypothesis` / `forecast` / `assumption` / `synthetic`),
  источники, место в источнике, цитата, уверенность, из чего выведено. Факт без источника не
  записывается. Отзыв (`retract`) не удаляет, а помечает — история сохраняется.
- **Пробелы `G…`**, **ключевые вопросы `Q…`**, **решения `D…`** с ответственными, метриками,
  основаниями, обязательствами и датами пересмотра.
- В документах ссылки `[C012]`; `pf.py check` находит битые и отозванные ссылки, факты без
  источников, синтетику в роли доказательства спроса.
- **Механическая сверка фактов:** цитата факта должна дословно найтись в сохранённом тексте
  источника, иначе факт не записывается; числа факта, которых нет в источнике, дают
  предупреждение (так ловятся пересказ «по памяти» и искажённые цифры — без участия модели).
- `pf.py impact --claim C005` — какие выводы, строки документов, решения и вопросы затронуты:
  по прямым ссылкам, по тегам (пробелы и вопросы, которые закрывало утверждение) и по
  основаниям решений; документы без прямых ссылок перечисляются для ручного просмотра.
- `check` также предупреждает о допущениях, на которые никто не ссылается (их отзыв нельзя
  отследить), о ссылках на отозванное в пробелах и решениях и об отсутствии независимой
  сверки обещаний (judge).
- При пересмотре субагент `judge` сверяет все документы с актуальным состоянием — ловит
  остатки старой картины, в том числе от прошлых пересмотров.

### Основные команды
```
python3 tools/pf.py status            # где мы
python3 tools/pf.py claim list        # на чём основаны выводы
python3 tools/pf.py check             # целостность ссылок
python3 tools/pf.py review            # что пора пересмотреть
python3 tools/pf.py decision edit --id D003 --trigger "..." --note "почему"   # уточнить решение (с историей)
python3 tools/pf.py gap edit G002 --new-text "..." --reason "..."            # уточнить пробел
python3 tools/pf.py source reviewed --id S003 --note "..."                   # подозрительный фрагмент разобран
python3 tools/pf.py cost              # сколько стоило (по журналам Claude Code)
python3 tools/pf.py report --html     # итоговый отчёт
python3 tools/pf.py kb search "отток после повышения цены"   # база знаний прошлых проектов
python3 tools/pf.py kb use K004       # перенести запись в проект с честным статусом
python3 tools/selftest.py             # самопроверка pf.py (для разработчика агента)
```

### База знаний между проектами
`projects/_kb/kb.jsonl` — то, что стоит помнить после проекта: факты с исходными источниками
(`kb promote Cxxx`), выводы агента (`kb add --kind lesson`), прошлые решения (`kb promote Dxxx`),
слова человека (`kb add --kind note`). В новом проекте запись становится тем, чего заслуживает
её происхождение: факт — фактом с тем же источником и предупреждением о давности, вывод агента —
только гипотезой, решение и слова человека — допущением. Поиск — по основам слов и триграммам
(русская морфология без словарей), навигация — теги и связи (`kb related`), исправление —
`kb retract` / `kb supersede` с историей; проекты, взявшие отозванную запись, увидят это в
`pf.py check`. Подробно — `AGENTS.md`, §8.

### Хуки Claude Code
- `SessionStart` → статус активного проекта (продолжение без повтора шагов).
- `PreToolUse` → запрет правки правил/инструментов агента во время работы (защита от команд
  из источников). Для разработки агента создайте пустой файл `.dev_mode`.
- `Stop` → `pf.py check` после каждого ответа. При ошибках целостности (ссылка на отозванное,
  факт без источника, синтетика как факт) хук не даёт закончить ответ и передаёт ошибки
  агенту — один раз за ответ, без зацикливания. Предупреждения ответ не блокируют.

## Режимы и замер качества
- **Быстрый (по умолчанию):** один документ `summary.md` с вариантами, условной стратегией,
  сверкой обещаний и планом проверки; основная модель — Sonnet. **Полный:** шесть документов
  этапов, остановка на выборе, Opus. Подробно — `AGENTS.md`, раздел 3а.
- Замер против обычного чата — `docs/benchmark.md`. На веб-задаче из 7 проверенных фактов у
  обычного чата подтвердились 3, у агента — 7. Быстрый режим стоил столько же, сколько
  обычный чат (1,32 против 1,42 USD), и после пересмотра оставил 2 устаревших места против 6.
- Как агента тестировали и чинили — `docs/overnight_report.md`.

## Ограничения
- Работа с сайтами: `pf.py fetch` не исполняет JavaScript — для таких сайтов агент использует
  WebFetch среды. Сайты с авторизацией не поддерживаются намеренно.
- Изображения анализируются моделью напрямую; аудио/видео — через расшифровку и кадры,
  которые готовятся вне `pf.py` (см. `docs/media.md`).
- Параллельные вызовы `pf.py` (субагенты) безопасны: хранилище блокируется на время команды
  (`projects/.lock`); загрузка страницы в `fetch` идёт вне блокировки.

## Проверка

```bash
python3 tests/smoke_test.py   # без сети и моделей, ~8 с; проекты во временной папке
```
Проверяет: факт без источника отклоняется, инъекция помечается, параллельные записи не
теряются, синтетика не становится фактом, отзыв ломает `check` и блокирует Stop-хук,
`impact`/`review` находят зависящие выводы и решения, отчёт собирается, MCP-сервер отвечает по
протоколу и отклоняет факт без источника так же, как CLI.
База знаний: факт переносится с источником, вывод агента — только гипотезой, синтетика и факты
без источника в базу не попадают, поиск учитывает морфологию, отзыв записи виден в `check`.
- Стоимость считается по журналам Claude Code и тарифам API (`tools/pricing.json`); в других
  средах расход вносится вручную `pf.py cost-add`.
- Синтетические интервью — только для гипотез.
