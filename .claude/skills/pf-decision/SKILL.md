# Фиксация решения и сопровождение

1. Для каждого принятого решения (обычно 2–5: направление, отказы, запуск теста, сообщение):
   ```
   pf.py decision add --title "..." --rationale "..." --owner "<роль>" \
     --basis C003,C007 --metric "..." --trigger "пересмотреть, если ..." --review-date YYYY-MM-DD
   pf.py decision commit --id D001 --title "<обязательство>" --owner "<роль>" --review-date YYYY-MM-DD
   ```
   Ответственные — роли («PM», «маркетинг»), не ФИО.
   В `--basis` включай не только факты, но и **допущения и гипотезы**, без которых решение
   было бы другим: именно они отзываются первыми, и решение должно всплыть в `pf.py review`.
2. `deliverables/summary.md` — одна страница для получателя: вопрос, ответ, почему, что
   делаем и не делаем, как проверим, когда пересмотрим, ключевые пробелы.
3. `pf.py report --html` → `deliverables/REPORT.md/html`. `pf.py cost` — добавь итог расходов
   в summary (раздел «Сколько это стоило»).
4. `pf.py stage tracking --next "Ждём новых данных; pf.py review еженедельно"`.

## Сопровождение (при каждом возвращении PM)
- `pf.py review` — наступившие даты, просроченные обязательства, отозванные основания,
  устаревшие источники. Скажи PM, **что нужно решить сейчас**, и предложи `/pf-revise`.
- Смена статуса: `pf.py decision status --id D002 --title revised|cancelled|done --rationale "..."`.
