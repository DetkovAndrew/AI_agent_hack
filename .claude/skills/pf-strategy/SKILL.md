# Продуктовая и коммуникационная стратегия

Методики: `product-strategy.md`, `comms-strategy.md`.
Шаблоны: `knowledge/templates/product_strategy.md`, `knowledge/templates/comms_strategy.md`.

1. **Продуктовая** (`deliverables/product_strategy.md`):
   аудитория и её задача (JTBD) → текущие альтернативы и почему их выбирают → выбранное
   направление → **осознанные отказы** (что не делаем и почему) → связь пользы с затратами и
   доходами (юнит-экономика/порядок величин, допущения явно) → ключевые риски.
   Каждое допущение, на котором держится стратегия (в т.ч. принятые PM на этапе выбора),
   **цитируй** как `[Cxxx]` там, где оно используется, — иначе при его отзыве `impact` не
   найдёт зависящие места (`pf.py check` предупреждает о непроцитированных допущениях).
2. **Коммуникационная** (`deliverables/comms_strategy.md`):
   аудитория и ситуация контакта → **барьер** понимания или выбора → ключевое сообщение →
   его подтверждение (proof points — только то, что продукт реально даёт, со ссылкой [C]) →
   роль каждого канала (в какой момент пути, какая задача) → чего не обещаем.
3. **Сверка обещаний.** Выпиши каждое обещание из коммуникационной стратегии и запусти
   субагента `judge` с задачей «соответствует ли обещание продуктовой стратегии и фактам»;
   несоответствия исправь. Таблицу сверки включи в `comms_strategy.md`. Вердикты зарегистрируй:
   `pf.py source add --kind analysis --title "Вердикты judge: обещания vs продукт" --text "..."`.
   Самопроверка основным агентом сверку не заменяет: автор склонен соглашаться с собой.
4. Покажи PM краткую выжимку (по 5 строк на стратегию), прими правки.
5. `pf.py check`, `pf.py stage validation --next "..."`.
