# Варианты и возражения

Методика: `knowledge/methods/options-and-objections.md`. Шаблон: `knowledge/templates/options.md`.

1. Сформулируй 3–5 вариантов. Обязательно:
   - **«Оставить как есть»** — честно: что будет, если ничего не менять (прогноз [C]);
   - **«Закрыть / свернуть направление»** — если это разумно рассматривать;
   - минимум один вариант, принципиально отличный по аудитории или модели дохода,
     а не «тот же, но побольше».
   Варианты различаются по сути (кому, какую задачу, за чей счёт), а не по тактике.
2. Для каждого: суть, для кого, какие факты за [C], на каких гипотезах держится [C],
   экономика (порядок затрат и эффекта — как `forecast` с допущениями), риски, что нужно
   проверить первым.
3. **Возражения.** Запусти субагента `red-team` на все варианты сразу. Включи в документ
   самое сильное возражение к каждому и свой ответ (или признание, что ответа нет).
4. Сравнительная таблица по критериям PM (`brief.decision_criteria`). Отметь, какие оценки
   основаны на фактах, а какие на гипотезах.
5. Рекомендация + условия, при которых рекомендация меняется («если Q003 окажется …, то B»).
6. `pf.py check`, затем `pf.py stage choice --next "Ждём выбора варианта PM"` и
   `pf.py set open_questions_to_human "Выберите вариант: A/B/C/D" --append`.
7. **Остановись.** Покажи PM таблицу и рекомендацию и спроси выбор. Не пиши стратегию до ответа.
   После ответа: `pf.py set chosen_option "B: ..."`, `pf.py set open_questions_to_human --clear`,
   `pf.py log "PM выбрал B: <причина>" --kind decision`, `pf.py stage strategy`.
