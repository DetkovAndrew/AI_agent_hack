# Исследование

Методики: `evidence-standards.md`, `data-analysis.md`, `ux-analysis.md`, `interviews.md`.

1. `pf.py focus` сводит факты, источники и пробелы по ключевым вопросам. Выбери пробел или
   противоречие, ответ на которое может изменить рекомендацию, порог или условия пилота.
   Для такого вопроса Q:
   - что уже есть в реестре: `pf.py focus --q Q001`, затем открой нужные утверждения или снимки;
   - что известно из прошлых проектов: `pf.py kb search "..."` → `pf.py kb use Kxxx --q Qxxx`
     (факт придёт со старым источником — проверь свежесть; вывод агента — только гипотезой);
   - если не хватает — передай субагенту `researcher` ID вопроса, пробела и условие смены выбора
     (независимые вопросы — параллельно). Для данных PM запиши способ получить их в пробеле;
   - таблицы → субагент `data-analyst` (скрипт в `analysis/`, результат — утверждения);
   - интерфейсы/скриншоты → разбор по `ux-analysis.md`, только видимое;
   - нужны гипотезы о мотивах аудитории → `/pf-interview`.
2. **Сопоставь источники.** Где источники расходятся — запиши оба утверждения и
   объясни расхождение (разные периоды, методики, определения). Одиночный вторичный
   источник на ключевой факт → `confidence low`, ищи подтверждение.
3. Выводы-интерпретации → `hypothesis` с `--derived` от фактов. Оценки будущего → `forecast`.
4. Что не удалось узнать → `pf.py gap add "..." --q Q001 --why "..." --impact high --how "..."`.
5. Закрой вопросы: `pf.py question close Q001 --claims C003,C007 --status answered|partial|unanswerable`.
6. Напиши `deliverables/situation.md` по шаблону `knowledge/templates/situation.md`:
   известно (факты), предполагаем (гипотезы), не знаем (пробелы), что это значит для решения.
   Каждое утверждение — со ссылкой `[Cxxx]`/`[Gxxx]`.
7. `pf.py check` — исправь ошибки. `pf.py stage options --next "..."`.
